# 原生可编辑 PPTX 高还原标准

当用户提供参考 PPT/截图，或明确要求“高还原”“复刻”“原生重建”“可编辑 PPTX”时，必须遵循本标准。它适用于 `pptxContractVersion: 2`；普通 HTML 预览不执行其中的 PPTX 构建或渲染。

## 目标

交付物首先是可编辑的 PowerPoint，而不是整页截图：文字、卡片、线条、表格和可表达的图表均保留原生对象。浏览器 HTML 是轻量编辑源；原生重建只在用户点击“导出 PPTX”或显式导出命令时执行。

## 导出路线

1. 以当前浏览器快照或用户提供的视觉参考作为版式依据；不要在普通 HTML 生成阶段预产出 PPTX、PNG 或追审文件。
2. 先使用通用 v2 原生对象映射。中文文字写入 `typeface: "Microsoft YaHei"`，不得只设置浏览器 `font-family` 或 PowerPoint 的默认字体。
3. 对视觉关键对象，在模型中使用导出专用约束，而非反复修改网页 CSS：

   ```json
   {
     "name": "cover-title",
     "type": "text",
     "frame": { "x": 74, "y": 236, "w": 690, "h": 175 },
     "nativeFrame": { "x": 56, "y": 205, "w": 640, "h": 190 },
     "nativeText": "从链接排序\n走向答案引用",
     "nativeTextStyle": {
       "fontFamily": "Microsoft YaHei",
       "fontSizePt": 51,
       "lineHeightPt": 52.5,
       "bold": true,
       "color": "#F4F8F5",
       "wrap": false
     }
   }
   ```

   `nativeFrame`、`nativeText`、`nativeTextStyle` 仅覆盖 PPTX 导出，不改变 HTML 的正常编辑与响应式预览。
4. 若通用映射不能保留卡片栅格、组合图表、标题分色或关键装饰的视觉关系，不要继续用 CSS 测量值做微调；为该页补齐命名的原生形状、文本、表格和图表对象，并以明确的原生坐标重建。
5. 只有 PowerPoint 无法原生表达的复杂图表/视觉，才允许使用声明过的局部图片回退；不得把整页或普通文字截图后冒充“可编辑 PPTX”。

## 不可退让的视觉合同

- 中文内容使用微软雅黑；标题、正文、页脚都在 OOXML 中写入 `typeface`。
- 从参考稿提取主色、背景色、强调色和边框色，使用精确 HEX；不得用 PowerPoint 默认主题色替代。
- 标题必须显式设置字号、行距、禁换行策略与框体；不得依赖 PowerPoint 自动缩小或默认 1.2 倍行距。
- 封面与各页主标题优先保证层级、基线、换行、字距观感和强调色；正文在其后。
- 卡片、圆角、连接线、胶囊、页码、页脚、表格与图表的留白/对齐必须作为一个整体校准，不只校准文字。
- 一页中可编辑的图表必须保留原始类别、数列、颜色与图例；表格必须是原生表格且内容在水平、垂直方向正确对齐。

## 导出验收

每次高还原 PPTX 导出都必须：

1. 渲染最终 PPTX 的每一页，并逐页与视觉参考或浏览器快照核对。
2. 重点检查封面、每页标题区、卡片栅格、图表、页脚和页码；出现明显的错色、错位、文字换行、重叠、裁切或对象缺失即继续修正。
3. 运行 `slides_test.py` 确认无画布溢出，并保留原生文本、表格、形状和图表的验证。
4. 在交付前确认：HTML 预览未因 PPTX 重建而变慢，且整个重建过程只发生在导出阶段。

高还原不是要求所有报告套用同一视觉样式；它要求在用户提供的视觉方向内，把可编辑性、字体、配色、版式和内容完整度一起还原。
